# Extension Guide

## When to extend the framework
Extend the framework when a rule, role, template, or preset improvement is reusable across more than one project.

## When not to extend it
Do not add one-off project quirks or temporary workarounds to the shared framework.

## Good extension examples
- a cleaner handoff structure
- a better audit log format
- a safer default for security review triggers
- a reusable project preset for a common project type

## Change discipline
- update the relevant file
- update VERSION.md
- document why the change was made
- keep the change small and reviewable
