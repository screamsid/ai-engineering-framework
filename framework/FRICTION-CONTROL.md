# Friction Control

Governance should reduce operational risk without destroying delivery velocity.

This framework exists to:

- improve safety
- improve consistency
- improve validation
- reduce hidden uncertainty
- preserve institutional learning

It must not become:

- process theatre
- checkbox bureaucracy
- escalation spam
- endless approval loops
- rigid workflow paralysis

## Core Principle

Block on risk. Warn on style. Learn from everything.

## Secondary Principle

The framework must be strict where failure is expensive and lightweight where flexibility is safe.

## What Should Block Work

Blocking should be reserved for:

- unresolved critical risk
- destructive actions without approval
- missing validation for high-risk work
- confidence below threshold without human validation
- unsafe security behaviour
- irreversible operations without safeguards
- missing rollback awareness for high-risk changes

## What Should Usually Warn Only

Warnings are preferred for:

- formatting inconsistencies
- incomplete wording
- minor documentation issues
- low-risk process gaps
- optional metadata omissions
- advisory best-practice deviations

## Human Validation Control

Human validation should happen:

- when uncertainty materially affects risk
- when confidence is below threshold
- when operational blast radius is large
- for critical or irreversible actions

Human validation should NOT happen:

- for every low-risk action
- for stylistic disagreements
- because the framework lacks confidence calibration
- because enforcement rules became overly broad

## Escalation Anti-Pattern

Too much escalation destroys trust.

If agents escalate excessively:

- operators stop paying attention
- humans bypass the framework
- governance quality collapses
- delivery slows unnecessarily

The framework should minimise unnecessary interruption.

## Friction Signals

The framework should detect:

- repeated low-value escalations
- approval spam
- repeated ignored warnings
- increasing delivery slowdown
- rising reviewer fatigue
- repeated process bypassing
- excessive mandatory reviews
- low-value validation steps

## Friction Review Questions

Reviewers should periodically ask:

- does this rule reduce meaningful risk?
- does this rule repeatedly block safe work?
- is this review producing useful findings?
- are humans bypassing the framework?
- is this memory item creating confusion?
- is this validator checking meaningful quality or just formatting?
- are we measuring safety or just enforcing ceremony?

## Lightweight Governance Model

Prefer:

- targeted controls
- proportional validation
- contextual rule injection
- concise rule cards
- confidence-gated autonomy
- adaptive calibration

Avoid:

- giant prompts
- universal mandatory approvals
- enforcing every best practice
- excessive metadata requirements
- deeply nested workflow chains
- rigid deterministic orchestration

## Calibration Over Restriction

When uncertainty repeats:

- improve calibration
- improve skills
- improve memory
- improve validation guidance

Do not immediately add another hard gate unless risk justifies it.

## Governance Failure Modes

Governance has failed when:

- operators actively avoid the framework
- agents spend more time satisfying process than solving problems
- approval loops dominate delivery
- memory becomes noisy and ignored
- telemetry becomes vanity reporting
- reviewers stop trusting escalations
- adherence becomes checkbox theatre

## Runtime Guidance

The runtime should:

- enforce high-value controls first
- prefer warnings over blocks where safe
- escalate proportionally
- support adaptive autonomy
- keep injected context small
- reduce operational noise

## Confidence Guidance

Confidence systems should:

- reduce unsafe autonomy
- reduce unnecessary escalation
- improve calibration accuracy over time

Confidence systems should not:

- create fear-driven escalation
- punish uncertainty reporting
- reward fake certainty
- encourage agents to game scores

## Completion Rule

The framework is healthy when:

- safety improves
- trust improves
- useful autonomy increases
- repeated mistakes decrease
- governance overhead stays proportional
- humans still want to use the system
